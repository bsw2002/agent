# 006：带治理边界的长期分层记忆

## 目标

在短期 `ChatMemory` 之外建立独立的长期记忆域，区分语义、情景和程序记忆，并为每条记忆记录作用域、来源、置信度、敏感级别、有效期、状态和版本。

核心原则是：对话摘要不是用户画像，模型推测不是事实，工具输出也不能自动变成永久记忆。

本次改动只发生在 `codexProject` 副本中。

## 新增模型

### 记忆类型

- `SEMANTIC`：稳定事实、偏好、约束，例如“后端代码使用 Java”。
- `EPISODIC`：发生过且需要追溯的事件，例如“某次部署失败并采取了回滚”。
- `PROCEDURAL`：可信工作流程或组织规则，例如“生产发布必须审批”。

### 作用域

- `USER`：同租户、同用户的跨会话记忆。
- `CONVERSATION`：只对某个经过身份哈希隔离的内部会话键生效。

### 来源

- `USER_EXPLICIT`
- `AGENT_CONFIRMED`
- `SYSTEM_POLICY`
- `TOOL_OBSERVATION`

来源不是装饰字段，它参与写入策略。当前公开 API 只产生 `USER_EXPLICIT + SEMANTIC` 记忆；原始工具观察被拒绝，程序记忆只允许可信系统策略产生。

### 生命周期与版本

每条记忆包含：

- `ACTIVE / SUPERSEDED / DELETED`
- `validFrom / validUntil`
- `createdAt / updatedAt`
- 乐观锁 `version`

删除采用软删除，保证审计和未来的数据恢复策略有落点；查询只返回有效且未过期的活动记忆。

## 写入治理

`MemoryWritePolicy` 在入库前执行：

1. 空值、长度和置信度校验。
2. 禁止把原始工具输出写成长期记忆，降低网页/工具提示注入形成“永久中毒”的风险。
3. 禁止用户或普通 Agent 写入程序记忆，避免一句对话改写高权限工作流。
4. Agent 确认型记忆要求至少 0.8 置信度。
5. 检测常见 API key、密码赋值、OpenAI 风格密钥和 JWT，明确拒绝保存凭据。

当前数据库内容尚未配置列级加密，因此即使请求标记为 `SENSITIVE`，凭据仍然拒绝入库。敏感级别用于后续的检索过滤、脱敏、加密和保留期策略，不能被误解为“现在可以安全存密钥”。

## PostgreSQL 存储

新增 `suvia_memory`：

- 所有记录都带 `tenant_id + user_id`。
- `scope_type + scope_key` 控制用户级和会话级可见范围。
- `content_hash` 用于同作用域活动记忆去重。
- 局部唯一索引只约束 `ACTIVE` 数据，删除后允许用户重新记忆相同内容。
- 所有单条读取和软删除都同时匹配租户及用户。

候选查询同时返回用户级记忆和当前会话级记忆，不会把其他会话的内容混进来。

与前两阶段一致，当前 DDL 使用启动时 `IF NOT EXISTS` 方便副本验证；生产应改用 Flyway/Liquibase，并为大表设计分区、归档和在线索引。

## 服务与检索

`LongTermMemoryService` 提供：

- `rememberExplicit`：用户显式保存稳定语义记忆。
- `recall`：按所有权与作用域取候选，再做轻量相关性排序。
- `forget`：带所有权与版本检查的软删除。

当前相关性排序对英文使用词项、对 CJK 使用字符词项，综合词项覆盖率、置信度和小幅作用域特异性加权；相关度相同时，当前会话记忆优先于用户级通用记忆。它是可离线测试的安全基线，不是最终检索器。下一阶段会把长期记忆纳入统一检索编排，使用 lexical + vector + metadata filter + reranker，并保留本地算法作为故障降级。

## API

新增：

- `POST /ai/memories`：显式保存一条语义记忆。
- `GET /ai/memories?chatId=&query=&limit=`：召回用户级及指定会话级记忆。
- `DELETE /ai/memories/{memoryId}`：软删除本人记忆。

响应使用 `MemoryView`，不泄露内部租户 ID、用户 ID、scope hash 或 content hash。

会话级写入必须显式提供 `chatId`；服务端将其转换为身份隔离后的内部键。用户级写入不会错误生成一个随机会话。

## 与业内方案对照

### Claude Code / Codex Harness

coding harness 中长期有效的内容通常来自项目规则、用户偏好和任务状态，而不是把全部聊天永久向量化。本实现把程序规则与用户事实分开，并禁止普通对话提升为高权限程序记忆，符合“指令来源决定权限”的安全原则。

### Mem0

Mem0 类方案强调从对话抽取、更新、合并和检索事实。本实现已经具备带 hash 的去重、来源、作用域和生命周期，但尚未实现模型驱动的 ADD/UPDATE/DELETE 决策。引入自动抽取前必须先做候选态、用户确认和离线事实准确率评测。

### Zep / Graphiti

Zep/Graphiti 方向强调时间有效性、实体关系和事实随时间变化。本模型预留 `validFrom/validUntil` 与 `SUPERSEDED`，但目前还没有实体图和矛盾解析；不能把当前表述成知识图谱。

### Letta

Letta 将核心记忆、归档记忆和工具化记忆管理结合。这里对应地把短期滚动上下文与长期记录拆开，并通过独立 API 管理长期记忆；未来可由受策略约束的 memory tool 调用，而不是允许模型直接写数据库。

### LangGraph Store

LangGraph 把跨线程 store 与线程 checkpoint 分开。本项目现在也形成三个清晰层次：聊天短期记忆、Agent 运行 checkpoint、跨会话长期记忆。三者有不同的生命周期和安全边界。

### OpenHands

事件流适合保存“发生了什么”，长期记忆适合保存“以后仍应使用的稳定信息”。运行事件不会被自动复制到长期记忆；只有经过确认的事件摘要才能在未来进入 `EPISODIC`。

## 测试

新增 `LongTermMemoryServiceTest`，覆盖：

1. 显式记忆的类型、来源、作用域、置信度和规范化。
2. 用户级记忆与当前会话级记忆同时召回，其他会话被排除。
3. 相关记忆排序优先。
4. 删除必须匹配所有者并执行软删除。
5. 密钥、原始工具观察和非系统程序记忆被拒绝。

本阶段长期记忆测试 4 个，配合上一阶段短期记忆测试共 9 个，失败 0、错误 0、跳过 0。

## 下一步

1. 增加 `PENDING` 候选表：模型只能提出候选，用户或高置信规则确认后才能激活。
2. 实现矛盾检测和 supersede 链，避免“用户喜欢 A”和“用户不再喜欢 A”同时生效。
3. 使用 pgvector + PostgreSQL lexical 搜索召回，并用 reranker 排序；过滤必须先于向量相似度。
4. 按敏感级别增加 KMS/信封加密、字段脱敏、TTL 和访问审计。
5. 增加 GDPR/个人信息保护所需的导出、删除、保留期和目的限制能力。
6. 记忆注入模型前使用统一 `ContextAssembler`，附带 memory ID、来源、时间和低信任标签。
