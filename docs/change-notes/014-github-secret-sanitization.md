# 014：GitHub 发布前敏感信息清理

## 变更目的

在不影响当前开发机直接启动的前提下，将项目发布到公开 GitHub 仓库，并避免提交数据库密码、模型 API Key、搜索服务 Key、MinIO 凭据和 VMware 内网地址。

## 配置分层

- `application.yml`：允许提交，只包含环境变量引用和无敏感信息的本地默认值。
- `application-local.yml`：当前开发机的真实配置，由 `application.yml` 自动导入，但已被 `.gitignore` 排除。
- `application-local.example.yml`：允许提交，帮助其他开发者创建自己的本地配置，所有值均为占位符。

因此当前开发机不需要把凭据写进系统环境变量；其他环境仍可通过环境变量、Secret 或自己的本地配置文件覆盖。

## Git 忽略项

新增忽略：

- 本地敏感配置文件；
- `.env` 文件；
- 运行日志与 `runtime` 目录；
- 本地 PDF 文献，只保留目录说明，避免误传个人信息或第三方版权材料；
- 文档和启动脚本中的本机绝对路径，统一改为可移植的占位路径；
- Maven 构建产物和本地依赖缓存继续保持忽略。

## 安全检查范围

发布前检查源代码、配置、脚本、测试和文档，确认真实 DashScope Key、搜索服务 Key、数据库密码组合、MinIO 默认凭据和 VMware 地址不会进入 Git 暂存区。

构建目录不提交；本地测试中的虚构字符串（用于验证脱敏逻辑）不属于真实凭据。

## 后续建议

已经在本地文件中使用过的第三方 Key 不应出现在截图、聊天记录或公开构建产物中。如果怀疑曾经对外暴露，应在服务商控制台轮换 Key，并更新本地 `application-local.yml`。
